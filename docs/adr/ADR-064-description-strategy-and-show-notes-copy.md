# ADR-064: Description Strategy — Copy from Show Notes by Default

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-02 |
| **Deciders** | Engineering, Content Operations |
| **Supersedes** | Hardcoded system prompt in `/api/process/summarize` |
| **Related** | ADR-014 (publishing-attribute processing rules), ADR-046 (prompt-driven Show Notes), ADR-055/056 (title alignment), ADR-057 (page taxonomy), ADR-059 (pre-show trim for summaries), ADR-060 (scheduled show windows), ADR-063 (progressive-reach transcript fetch) |

---

## Context

The paragraph `description` on a video record — the text that ships to the YouTube upload — has, until now, been generated one of two ways:

1. **Ingest-time text.** For Zoom / Fireflies / Kaltura, the platform supplies its own description; we store it verbatim.
2. **`✨ Generate from transcript`.** For records without ingest description, the operator hits a per-card button that calls `/api/process/summarize` — an LLM one-shot that reads the transcript and returns a 2–4 sentence summary.

Two friction points have surfaced:

- **The description ignores the Show Notes.** ADR-046 already produces a curated M/L/T/C breakdown of the video with high-signal timestamps. The description pipeline burns another LLM call to re-derive the same thing badly (12,000-char truncation vs. 400,000-char show-notes context; single-shot vs. the show-notes' explicit section prompt). Operators end up with a Show Notes doc that names the interesting moments and a description that misses them.
- **The transcript-mode prompt is buried in code.** `/api/process/summarize` hardcodes its system prompt. Any tweak — different sentence count, banned phrasings, house style — requires a redeploy.

Separately, when we DO want to lift Show Notes into the description, we hit a format mismatch: Show Notes are stored as a Google Doc (rendered from Markdown), the YouTube description field is plain text with two special affordances (chapter cues at `HH:MM:SS`; URL autolinkification) and no markdown rendering. Naïvely pasting the Show Notes markdown emits literal `## Key Moments` and `**bold**` characters and misses YouTube's chapter picker entirely.

---

## Decision

### 1. Two-mode description strategy, stored per-org

New config `data/description-config.json`:

```json
{
  "mode": "copy_show_notes" | "generate",
  "prompt_text": "...",
  "updated_at": "iso",
  "updated_by": "user_id"
}
```

- `mode: "copy_show_notes"` (**default**) — the description is a deterministic conversion of the record's current Show Notes doc. No LLM call. Falls back to `generate` when the record has no `summary_doc_id` yet.
- `mode: "generate"` — the pre-ADR-064 path. LLM one-shot from the transcript, using `prompt_text` as the system prompt.

`prompt_text` is used in the `generate` mode AND as the fallback prompt for `copy_show_notes` records that lack Show Notes. Editable via the UI; the embedded default ships so the pipeline works before anyone tunes it.

New API: `GET /api/description/config` (public), `PUT /api/description/config` (Admin-only, same auth pattern as `/api/summary/prompt`).

### 2. `showNotesToDescription()` — deterministic markdown → YouTube-plain-text

The conversion (`web/src/lib/showNotesToDescription.ts`) does the following:

1. **Strip the `🤖 Generated by video-sync summary-prompt vN on <iso>...\n---\n` banner** the `summaryGenerate` pipeline prepends — same strip already used by the LLM-copy fallback path.
2. **Rewrite `- [HH:MM:SS] Text` bullets into `HH:MM:SS Text` chapter cues.** Also accepts numbered/asterisk bullets. Also accepts `[H:MM:SS]` and `[MM:SS]` forms, normalising to zero-padded `HH:MM:SS`.
3. **Flatten heading markers.** `## Chapter` → `Chapter` (keeps the visual heading text; drops the `#` glyphs that would appear literally on YouTube).
4. **Strip inline emphasis.** `**bold**`, `_italic_`, `` `code` `` all become plain text.
5. **Validate + repair chapter cue rules.** YouTube's picker requires (a) first cue at `00:00:00`, (b) strictly increasing timestamps, (c) at least three cues. If the extracted cues have ≥3 monotone entries but the first isn't zero, we prepend a synthetic `00:00:00 Opening`. If any rule can't be repaired, the bare `HH:MM:SS` lines stay in the body — they read fine as plain text, YouTube just doesn't render them as clickable jumps.
6. **Collapse 3+ blank lines to one.** Google Doc export is generous with blank lines; YouTube honours them 1:1.
7. **Enforce YouTube's 5000-char cap.** Truncate at the last complete line under the limit, append an ellipsis.

Fully deterministic — no LLM, no per-record variation.

### 3. Show Notes prompt gets belt-and-braces chapter-cue enforcement

`DEFAULT_PROMPT_TEXT` in `lib/summaryPrompt.ts` gets two additions:

- Timestamps must be **EXACTLY** `[HH:MM:SS]` — always 2-digit hour, minute, second (e.g. `[00:14:32]`, not `[14:32]` and not `[0:14:32]`).
- The **very first bullet** of the first chapter's Key Moments section MUST have timestamp `[00:00:00]` — a generic opener like "Show begins" is fine. This anchors the YouTube chapter list.

The prompt tries to get the model to comply on the first shot; `showNotesToDescription` guarantees a legal chapter list even when it doesn't. Records generated pre-ADR-064 continue to work because the converter is lenient about timestamp format.

### 4. `VideoCard`'s regen button reflects the mode

Two buttons on the card fired the same handler (`generateDescriptionFromTranscript`): a small "✨ Regenerate from transcript" next to the Description label, and a larger "✨ Generate from transcript" in the empty-state block. Both now:

- Read `getDescriptionConfigCached()`.
- Render **📋 Copy from Show Notes** when `mode === "copy_show_notes" && summary_doc_id`.
- Render **✨ Regenerate from transcript** (or "Generate from transcript") in all other cases.
- Handler branches on the same condition. Copy mode = one fetch + `showNotesToDescription()` + `update_metadata`. Generate mode = existing LLM path with ADR-060 trim.

Event log distinguishes: `DescriptionCopied: … — from Show Notes` vs. `DescriptionGenerated: … — from transcript` (with `— from transcript (Show Notes fallback)` when the fallback fired).

### 5. Config page absorbs both prompts

ADR-057 put maintenance-ish knobs on Maintain and setup-ish knobs on Config. The Show Notes prompt sat on Maintain because it drove a bulk-regen action; the new description-strategy panel is unambiguously Config. Both now live on Config as sibling panels below Series Registry. Maintain drops the "📄 Show Notes Prompt" toggle button and reverts to a pure catch-up canvas.

## Consequences

**Positive**
- Descriptions inherit the Show Notes' curated timestamps AND become YouTube-chapter-clickable in one step, no extra LLM cost.
- The transcript-mode prompt becomes tunable in the UI — a house-style tweak stops being a redeploy.
- Prompt lives beside the Show Notes prompt on Config, giving operators one place to look when tuning generation.
- ADR-046 Show Notes + the paragraph description stay in structural harmony — one is a superset of the other.

**Negative / trade-offs**
- **Descriptions drift from Show Notes as Show Notes are re-generated.** After a Show Notes regen, the description reflects the previous version until the operator re-clicks Copy. Not silent — the Show Notes lozenge shows the current prompt version and the operator can eyeball; but it's a manual sync. If this becomes friction, a follow-up ADR can auto-re-copy on Show Notes regen.
- **`copy_show_notes` fallback still costs an LLM call.** Records without Show Notes fall through to the LLM path, so the cost profile only improves for records that have Show Notes. Ordering Show-Notes-backfill (ADR-052) before Description-refresh gets you full coverage.
- **Show Notes' first-bullet-at-`00:00:00` rule can produce awkward openers.** "Show begins" is generic; operators may want to edit for polish. Since the Show Notes doc is a native Google Doc, they can — the change persists to the description on next Copy.
- **The 5000-char cap can truncate long-form Show Notes**. Multi-chapter docs from 3-hour livestreams routinely exceed 5000 chars. Truncation happens at the last complete line, so the description reads cleanly, but the tail chapters get cut. Deferred: a "prioritise chapter cues over prose" mode that keeps chapter lines and drops descriptive bullets to fit.

**Downstream effects to watch**
- **ADR-046 Show Notes prompt evolves.** Both new rules (2-digit HH always, first bullet at 00:00:00) are additive — old generated docs still parse. But new prompt versions should keep the chapter-cue-friendly conventions.
- **ADR-057 Config vs. Maintain split.** Config now carries both prompts; keep an eye on it becoming crowded. If more prompts get added (a per-series prompt override, for example) the Config page may need collapsible groups.
- **`/api/process/summarize` no longer has an embedded prompt.** Old callers (if any survive outside the description-generation path) get the config's prompt whether they want it or not. Grep of the code shows no other callers today; call this out if a future service starts using the endpoint.

## Alternatives Considered

| Alternative | Reason Not Chosen |
|-------------|-------------------|
| Keep the transcript-LLM path, teach the prompt about chapter cues | Doesn't help — the description would still need markdown-to-plain conversion at export time, AND we'd keep paying for an LLM call whose signal we already have. |
| Store the description as markdown; convert at YouTube-upload time | Two sources of truth for the same field. Ships the markdown to Discord webhooks / Drive footer / anywhere else that consumes description and expects plain text. Chose "description is always plain text; Show Notes is always markdown." |
| Merge description and Show Notes into a single artifact | The two have different audiences (YouTube skim vs. archive drilldown), different length profiles, and different mediums (plain text vs. rendered doc). Merging loses the per-artifact affordances. |
| Auto-copy on Show Notes regeneration | Would eliminate drift but adds a mutation the operator didn't request. Deferred until the manual re-copy proves painful in practice. |
| Bulk "🔄 Refresh descriptions from Show Notes" maintenance card | Legitimate but scoped for a follow-up. Per-record Copy button + per-record Push button covers the current curation flow; a bulk sweeper is worth adding once operators actually have a lot of drift to catch up on. |

---

## Out of Scope

- Bulk description refresh (Option B in the pre-decision discussion). If needed, the shape mirrors ADR-052's Show Notes backfill — walk records with `summary_doc_id`, compute `showNotesToDescription()`, compare, batch-mutate.
- Per-series prompt overrides.
- Automatic re-copy on Show Notes regenerate.
- Automatic re-push to YouTube when description changes locally. The existing `↗ Push title + description to YouTube` button is manual by design; a "watch for changes and push" mode would need explicit operator opt-in.
